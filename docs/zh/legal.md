# 法律与分发说明

本文是操作层面的合规指南，不构成法律建议或知识产权保证。具体分发者适用的规则取决于其产品、构建、
司法辖区和分发渠道。

## Anmixiu 许可证

Anmixiu 使用 MIT 许可证，允许商业、专有和开源使用、修改与再分发。分发软件副本或软件的重要部分时，
必须保留完整的 Anmixiu 版权与 MIT 许可声明。每个发布的 Anmixiu crate 都配置为在源代码包中包含
仓库的 `LICENSE` 和 `README.md`。

MIT 文本声明不提供担保，但不会免除强制性的消费者、产品、隐私、无障碍、出口或其他监管义务。它也不
包含明确的专利许可条款、商标许可或知识产权赔偿。

## 第三方依赖

Cargo 依赖保留各自的许可证；Anmixiu 的 MIT 许可证不会替代它们。`Cargo.lock` 当前的常规依赖图
采用宽松的许可证表达式，不含仅以 GPL、AGPL、LGPL、MPL、SSPL 或其他源代码披露许可证声明的
依赖。这只是一份快照：目标选择、feature、依赖升级和应用额外引入的依赖都可能改变结果。

每次发布前，应根据每个发布目标与 feature 组合的准确锁定依赖图生成声明。分发源代码或二进制文件时，
保留每项依赖的版权声明和所选许可证文本。在当前 macOS 依赖图中，除所选 MIT 条款外，还应特别注意
`slotmap` 的 Zlib 许可证与 `unicode-ident` 的强制 Unicode-3.0 条款。开发和基准依赖不属于
下游应用的常规链接图，但重新分发其源代码或二进制文件时，相关条款仍然适用。

可用的发布检查包括：

```sh
cargo metadata --locked --format-version 1
cargo tree -p anmixiu --edges normal --all-features --target aarch64-apple-darwin \
  --format '{p}\t{l}'
cargo package -p anmixiu --list
```

对于发布的应用，可以使用 `cargo-about` 等许可证声明生成器。应审核生成结果，不能把自动 SPDX 扫描
当作法律结论。

## 平台软件、字体与分发渠道

仓库通过 Rust 依赖调用公开的 macOS AppKit、CoreText、Metal、CoreGraphics、QuartzCore 与
Grand Central Dispatch API，不捆绑 Apple 系统框架或系统字体文件。构建或分发 Apple 平台应用
的开发者仍需负责遵守 Xcode 与 Apple SDK 条款、代码签名与公证要求、适用的 App Store 规则、
entitlement、隐私披露，以及 Apple 名称或商标的使用规则。

应用选择具名字体时，需要另行确认该字体已安装，或者预期的嵌入和再分发已获许可。引用系统字体族并不
等于获得分发字体文件的许可。

## 无障碍与受监管产品

当前实现不提供无障碍树或辅助技术集成。下游应用不能仅仅因为使用 Anmixiu 就声称自身具备无障碍
能力。受无障碍法律、公共部门采购规则、医疗或安全监管、金融监管或类似要求约束的产品与服务，需要进行
特定于产品的审查，并且可能需要当前框架范围之外的能力。

## 名称、专利与来源

软件许可证不授予 `Anmixiu` 名称或任何第三方名称的权利。项目名称、域名或注册信息检索不能替代商标
许可调查；计划商业发布的维护者应在每个目标市场中，针对相关软件和技术类别进行司法辖区与类别特定的
调查。

`Anmixiu` 也是“安迷修”的直接拼音写法；该名称被用于商业运营的《凹凸世界》（*Aotu World*）角色。
这一事实本身不能确定软件构成商标侵权，但会产生实质性的关联与混淆风险。在此名称上积累商业商誉前，
应在各目标市场的相关软件和技术类别中检索完全相同、近似、中文字符和音译商标；如果许可状态不确定，
应考虑使用其他名称。

任何仓库扫描都不能证明不存在全部软件或用户界面专利风险。具有实质商业风险敞口的采用者应针对其实际
产品和市场评估专利风险。贡献者必须遵守仓库的代码来源政策，并披露任何源自第三方材料的代码，以便在
发布前审核其许可证。
